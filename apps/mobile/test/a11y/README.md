# Flutter a11y-gate checklist (c12, updated for tokens v1.3.0)

The `a11y-gate` skill's WCAG 2.2 AA checklist, mapped to the test or source
that covers each item in `apps/mobile`, under the D-6 focus model (DESIGN.md
"Flat 2.0 controls": no strokes anywhere; boundaries and focus are fills).
Nothing here has run yet: the tests are written statically and run once at
the c13 boundary (VLBV). An item is only **passed** when its test output is
recorded there.

| Checklist item                                     | How it is covered                                                                                                                                                                                                                                                                                                                  | Where                                                                                                                    |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Text contrast ≥ 4.5:1 (1.4.3) in both themes       | `textContrastGuideline` on every in-scope state, dark and light, at 375; token pairs for `on-control`, placeholders, `on-focus`, `on-selected`, `on-control-invalid`, `on-ember`                                                                                                                                                   | `kmA11yGate` (`test/support/km_a11y.dart`); `focus_fill_test.dart` "fill contrast"                                       |
| Control boundaries ≥ 3:1 by fill (1.4.11)          | `control` against `bg`, `bg-2`, `surface`, `card` (the only surfaces a control may sit on)                                                                                                                                                                                                                                         | `focus_fill_test.dart` "fill contrast"                                                                                   |
| No borders, outlines, rings or divider lines (D-6) | Every in-scope state is scanned for `BoxDecoration.border`, shape sides and `Divider`s                                                                                                                                                                                                                                             | `focus_fill_test.dart` "Flat 2.0: no strokes"                                                                            |
| Focus visible by fill, ≥ 3:1 (2.4.7, 2.4.11)       | `focus` against every allowed surface and against each unfocused fill (`control`, primary, selected, danger, invalid); every kit control (buttons, icon button, segmented, toggle chip, checkbox, radio, select, list row, text field) is Tabbed to and must render the `focus` fill; the nav item takes the whole-item focus fill | `focus_fill_test.dart`, `adaptive_nav_test.dart`; kit: `lib/shared/ui/km_states.dart` (`KmInteractive`, `KmStateColors`) |
| Focus only for keyboard (`:focus-visible`)         | `KmInteractive` uses the focus _highlight_ (traditional mode), so a tap never leaves a focus fill; shadcn buttons run with `disableFocusOutline` and the fill from `KmStateColors`                                                                                                                                                 | `km_states.dart`, `km_button.dart`                                                                                       |
| Every actionable element has an accessible name    | `labeledTapTargetGuideline` on every state; kit controls require a label (`KmButton.label`, `KmIconButton.label`, `KmCheckbox.label`, `KmRadio.label`, `KmSwitch.label`, `KmSelect.label`)                                                                                                                                         | kit; `kmA11yGate`                                                                                                        |
| Target size ≥ 24 (2.5.8); 44 preferred             | `MinimumTapTargetGuideline(24×24)` on every state; nav items ≥ 48×44 (bar), 80×64 (rail), 44 tall (links); `sm` buttons are 36 only with a fine pointer (desktop), otherwise 44                                                                                                                                                    | `km_a11y.dart`, `adaptive_nav_test.dart`, `kmFinePointer` in `km_button.dart`                                            |
| Keyboard reachable, logical order, no trap         | Tab order skip link → brand → start → theme → sign in/account → (rail at medium) → page → (bar at compact); skip link moves focus to main; Escape closes the account menu and returns focus                                                                                                                                        | `frame_a11y_test.dart`; `OrderedTraversalPolicy` in `lib/app/frame/km_app_frame.dart`                                    |
| Focus survives the nav morph                       | Focus on a destination stays on the same destination after crossing 600/1024                                                                                                                                                                                                                                                       | `adaptive_nav_test.dart`                                                                                                 |
| State not by colour alone                          | Selected segments and toggle chips add a check icon; invalid fields add the error line (icon + text); switches move the thumb; status pips sit beside text; speaking is a badge next to the state text; current tab/nav item announced as selected                                                                                 | `km_controls.dart`, `km_selection.dart`, `km_fields.dart`, `km_feedback.dart`, `km_nav_bars.dart`                        |
| Images/media labelled; decorative excluded         | Brand mark, nav glyphs, avatars, orbs and speaking badges are `ExcludeSemantics`; adjacent text names them                                                                                                                                                                                                                         | `km_brand.dart`, `km_glyphs.dart`, `km_avatar.dart`, `km_orb.dart`, `km_feedback.dart`                                   |
| Reduced motion honoured                            | Every in-scope state settles with no running animation under `disableAnimations`; focus/hover fill transitions and the nav morph are instant; the account menu appears without animation                                                                                                                                           | `reduced_motion_test.dart`, `adaptive_nav_test.dart`, `frame_a11y_test.dart`; `KmMotion`, `KmNavMorph`                   |
| Live regions announce status                       | Field errors and the room's "You joined" notice are `liveRegion`                                                                                                                                                                                                                                                                   | `km_fields.dart` (`KmFieldError`), meeting_room feature                                                                  |
| Tooltips (1.4.13)                                  | Toast style, 500 ms hover delay, never the only copy of information (`excludeFromSemantics`, the control keeps its name). **Open:** Escape-to-dismiss is Flutter's default tooltip behaviour and is not asserted by a test                                                                                                         | `km_feedback.dart` (`KmTooltip`), `app_theme.dart`                                                                       |
| Large text does not overflow                       | **Not covered yet.** No test pumps a text scale above 1.0; open item for c13                                                                                                                                                                                                                                                       | —                                                                                                                        |
