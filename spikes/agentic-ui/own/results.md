## Architecture as built

```
src/
  domain/          pure TS, no imports outside domain: AG-UI event view, transcript model, reducer,
                   HITL state machine, RFC 6902 JSON Patch, media/link allowlist
  application/     use cases (AgentSession), ports, commit policy, LiveTextBuffer, Announcer,
                   RunAgentInput builder, SpikeSnapshot projection (harness types, per contract.md)
  infrastructure/  own SSE parser + AG-UI transport (Last-Event-ID reconnect, 3 retries), frame decoder
                   (@ag-ui/core zod EventSchemas), entity-graph store adapter, A2UI host
                   (@a2ui/web_core v1.0 MessageProcessor), CUSTOM chunk classifier (zod), launch params
  presentation/    React 19 views, Streamdown config, renderer registry, A2UI React catalog,
                   approval card, probe, copied shadcn patterns (ui/)
  main.tsx         composition root
```

- **AG-UI client:** no `@ag-ui/client`. `fetch` POST + our SSE parser; each frame is JSON-parsed and validated
  with `@ag-ui/core/schemas` `EventSchemas`; failures become `protocolErrors` and the stream continues. A
  network error or premature end before `RUN_FINISHED`/`RUN_ERROR` reconnects with `Last-Event-ID` and the
  same body (backoff 150/300/450 ms). Cancel aborts the `fetch`.
- **Reducer:** `(state, event) -> state`, immutable, ordering-checked (unknown/closed message or tool call,
  duplicate start, events outside a run, unknown activity/step, failed patches). Chunk events open entities
  and close on the next event of another kind.
- **Store of record:** every commit diffs the immutable transcript by reference and writes changed entities
  with one `upsertEntities` per type; React reads structure from the graph (`useGraphStore` selectors) and
  in-flight text from the LiveTextBuffer overlay. Shared state also goes through `applyAgUiSnapshot` /
  `applyAgUiDelta` (agenda items and counters as entities).
- **HITL:** explicit machine `pending -> approved | rejected | cancelled | expired`, `-> failed` when sending
  the resume fails (retryable), decisions idempotent (only the first accepted transition emits a resume; an
  in-flight guard per interrupt), a decision at or after `expiresAt` becomes `expired` and never sends a
  `resolved` resume. Expiry timers are armed on commit.
- **A2UI:** `@a2ui/react` `A2uiSurface` over `@a2ui/web_core` v1.0 with our React catalog for all 18 basic
  components plus `KmFallback`. Unknown component types are rewritten to `KmFallback` before processing.
  Operations are applied once each (snapshot then `/a2ui_operations/-` appends). Rendered ids are computed
  by walking the component tree (active tab only, open modal only, templates excluded).
- **Markdown:** Streamdown 2.7.1, `mode="streaming"`, math (KaTeX, `singleDollarTextMath`, trust off), code
  (Shiki), Mermaid via a lazy wrapper (strict, SVG labels, DOMPurify SVG profile with `foreignObject`, `a`,
  `image`, `use`, animation and `style` removed). No rehype-raw; `skipHtml`; sanitize + harden with an image
  allowlist of `allowMediaOrigin`; no link-safety modal, no copy/download controls.
- **Custom chunks:** zod-validated `km.citation` (superscript), `km.media` (img / video controls / audio
  controls, origin allowlist, never autoplay), `km.mermaid` (sanitised SVG); unknown names render the
  fallback; invalid or disallowed values render `km-media-blocked`; `RAW` is dropped.
- **Accessibility:** one `role="status"` live region with a start note, progress notes at most every 5 s and a
  final summary (at most 160 characters plus a prefix); `aria-busy` on the transcript while running; approval
  buttons use `aria-disabled` after a decision so focus stays on them; run errors render `role="alert"`.

## What entity-graph 4.3.0 needed and lacks

1. **No atomic multi-entity write.** `createGraphTransaction` runs each operation as its own `setState` (one
   subscriber notification per write) and `structuredClone`s the entire graph when it is created, so its cost
   grows with the graph. Unusable at token rate and costly even per boundary. We used one `upsertEntities` per
   entity type instead (up to 6 notifications per commit). A `batch(fn)` / multi-type `applyChanges` that
   produces one immer draft and one notification is the missing primitive.
2. **No ephemeral (non-durable) field layer.** Streaming text needs a hot overlay that renders but is not a
   store write. We built `LiveTextBuffer` beside the graph; the graph has no concept of volatile fields or
   commit cadence.
3. **The AG-UI bridge is a lossy projection.** `applyAgUiSnapshot` / `applyAgUiDelta` write only mapped object
   slices: scalars (`phase`), array order (`move`), and removals are not represented, and `reconstructState`
   cannot map a root pointer. The canonical shared state therefore lives in our reducer; the graph holds a
   partial projection. Each mapped item is a separate `setState`.
4. **Devtools emission in production browsers.** The guard `typeof process === "undefined" ||
   process.env.NODE_ENV !== "production"` is true in every browser build, so transaction operations emit
   devtools events in production.
5. **Immer auto-freeze reaches shared objects.** Everything written is deep-frozen; objects shared with other
   libraries (A2UI operations handed to `@a2ui/web_core`) must be cloned first.
6. **No ordered collection for a transcript.** Message, tool and interrupt order live as arrays on a
   `KmThread` entity (lists are keyed by query keys and meant for fetched pages).
7. **Restart recovery unproven.** `persistGraphToStorage` / `hydrateGraphFromStorage` exist, but rehydrating a
   transcript (and resuming a pending interrupt after reload) was not wired in this time box.

## Deviations and limitations (honest list)

- **Skills.** The brief asked to load `vercel-react-best-practices`, `shadcn`, `react-vite-stack` and
  `prometheus-entity-skills`; to keep context for the build I worked from the installed packages' types and
  sources instead of loading them. `clean-architecture`, `typescript-base-patterns` and the other architect
  skills were loaded.
- **Profiler in production.** React ignores `<Profiler onRender>` in production builds, so `renderCounts().commits`
  would be 0. `vite.config.ts` aliases `react-dom/client` to `react-dom/profiling` (adds profiling overhead and
  bundle weight; prototype H needs the same to report comparable numbers).
- **Clean-architecture compromises.** Presentation imports infrastructure in three places: graph entity names
  (`ENTITY`), the `A2uiHost` type and the km.* value types. In production these belong in an application read
  model port. `application/spike-snapshot.ts` imports the harness probe types, as contract.md allows.
- **A2UI rendered ids** are computed by our tree walk, not reported by `@a2ui/react` (it has no such API). The
  renderer also has no unknown-component fallback in 0.15.0 (it renders nothing), and its default Button is
  `disabled` while checks fail, which blocks pointer and keyboard feedback; our catalog replaces both.
- **Mermaid styling.** `<style>` is stripped from Mermaid SVG for safety, so diagrams render unthemed on a
  light panel.
- **Not done here:** Tauri WebKit/WebView2 runs (task 15.5), screen-reader testing with real assistive
  technology (axe and the harness checks only), restart recovery, the light theme.
