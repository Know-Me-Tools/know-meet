# Shape: Keep up with the conversation

Status: candidate interaction brief, not implemented or verified.  
Origin KM-LOCAL-MEETING-CATCHUP v0.1-draft. Scope KMT-1–3, native binding a579cadfd812a5cf531e6196933f9a5b7592fb8e0ac73b99cfba232e4e02f80b.

- **Job:** A browser guest needs to catch up without interrupting the meeting. Keep video and the microphone controls in place. Add a distinct, secondary **Transcript** control with an accessible name. Use the existing Chat panel and Recordings history affordances as visual references; neither becomes a generic share surface. This is an Operate surface in the existing KnowMeet design system.
- **Start:** The requester sees **On this device · Only you can see this transcript**, selected model language and actual measured download footprint, then an explicit **Download model** action. Show disabled/unsupported, download/cancel/retry, and ready states without reading room audio until the separate room prompt records affirmative assent. For other participants, show copy-readable consent terms and actual capture status, not a transcript button. Explain if the room contains a participant who cannot acknowledge the needed consent version.
- **Catch up:** Keep the timeline readable at idle, with “Live”/“Waiting for consent”/“Paused” visibly distinct. Stable timestamped lines and a compact search box come before optional AI. A result opens settled text, not an imaginary recording; scrolling pauses tail-follow, with a **Back to live** affordance. Provisional lines never enter search. No-results copy should say “No settled text matches yet” and offer clearing the query or waiting; no external autocomplete. If lag exceeds capacity, mark the affected interval and keep the meeting controls responsive.
- **Keep or remove:** On leave, report which text was retained and any gap; use historical browser-local status for incomplete or evicted content. In history, distinguish the transcript from video/audio, offer local delete with explicit scope, and leave independent WebM files untouched. No automatic download, sync, share link, or invitation. Local retention never implies device-wide encryption or ownership beyond the browser profile.
- **Constraints:** Use current shadcn components, fill-based contrast and focus, existing Flat 2.0 tokens, both themes, screen reader labels and non-spam status regions, and existing adaptive layout without new responsive promises. Lazy-load model/worker only on opt-in; subscribe to derived settled search state, not raw PCM/worker events. Paid agent and local generative add-ons remain deferred; existing recording dialog, release machinery and meeting admission stay unchanged.

Context: Impeccable shape on apps/web using inherited PRODUCT.md and DESIGN.md, local Prometheus UI/UX protocol, focused UI UX Pro Max search/empty-state and accessibility lookup, and Vercel React state/lazy loading guidance. The predecessor’s local recording success is preserved; render and behavior evidence are future phase-end work, not a result of this brief.
